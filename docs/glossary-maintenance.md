# K-Move 용어집 관리

## 기준 데이터

`src/data/glossary.json`이 LMS 용어 콘텐츠의 기준입니다. 이번 정리는 기존 239개 항목을 유지하며, 각 항목에 영어, 한국어 발음, 뜻, 정의, 활용 예시를 제공합니다.

- `id`: 변경하지 않는 고유 식별자. 새 항목은 중복되지 않는 영문 kebab-case ID를 사용합니다.
- `english`: 영어 표제어. 목록은 이 값으로 A–Z 자동 정렬합니다.
- `pronunciation`: 한국어 독음을 괄호 없이 입력합니다. 화면이 `[...]`를 붙입니다. 한글 독음은 학습을 돕기 위한 근사 표기이며 IPA가 아닙니다.
- `korean`: 디자인 현장에서 사용하는 한국어 명칭. 케이스 스터디·엠퍼시 맵·프로토타입처럼 통용되는 외래어와 CTA·IA·WCAG 같은 원어/약어를 살립니다. 설명을 위해 억지로 직역하지 않습니다.
- `description`: 초보자가 이해할 수 있는 정확한 정의. 필요한 실무 주의사항은 `[실무 참고]` 뒤에 기록할 수 있습니다.
- `example`: 해당 개념이 드러나는 구체적인 디자인·리서치·업무 상황 한 문장.
- `aliases` (선택): 이전 한국어 번역과 통용 표기·띄어쓰기 변형을 담는 검색어 배열. 표제어를 바꾸더라도 이전 표현으로 검색할 수 있게 유지합니다. `glossary.ts`가 영어·발음·한국어·정의·예시와 함께 검색합니다.
- `letter`: 원본에 보관하는 첫 알파벳. LMS는 `english`의 첫 글자에서 다시 계산하므로 필터와 정렬이 일치합니다.
- `lessonId` (선택): 처음 제작한 세 전용 UI 실습을 연결합니다. 값은 `cta`, `hamburger`, `carousel`입니다. 그 외 실습은 아래의 별도 실습 데이터에서 같은 용어 ID로 연결합니다.

새 용어를 추가하면 전체 개수, A–Z 정렬, 검색 대상과 페이지 수가 데이터에서 계산됩니다. 첫 화면이나 필터 숫자를 따로 수정하지 않습니다. 기존 용어의 수정은 같은 `id`를 유지합니다.

## 표기와 설명의 원칙

영어 표제어는 유지하고, 한국어 명칭과 쉬운 설명을 분리합니다. 예를 들어 `Case study / 케이스 스터디`로 표시하고 정의에서 프로젝트의 문제·판단 근거·역할·결과를 보여 주는 자료라고 설명합니다. `Fidelity / 피델리티`도 정의에서 시각 표현·콘텐츠·인터랙션의 구체화 수준을 설명합니다. 접근성·근접성·서체·시각적 위계처럼 자연스럽고 정확한 한국어는 유지합니다.

표기를 수정하면 `glossary.json`만 바꾸지 않고 `learning/entries.json`의 설명과 관찰 포인트, `practice/entries.json`의 공개 실습과 `takeaway`, 관련 렌더러의 고정 문구를 함께 확인합니다. 기존 세 전용 데모의 한국어 명칭은 `VisualGlossaryLesson.tsx`에 별도로 있으므로 같은 용어의 `korean` 값과 맞춥니다. 단순 문자열 치환 후에는 한국어 조사와 띄어쓰기, 원래 뜻이 달라진 문장이 없는지 검토합니다.

자료의 번역이나 권장 수치를 그대로 정답으로 옮기지 않습니다. UI를 외형만으로 설명하거나 버튼과 CTA를 같은 말로 처리하지 않습니다. 로파이·하이파이, 와이어프레임·목업·프로토타입은 서로 다른 구분이며 반드시 거쳐야 하는 한 줄의 순서로 만들지 않습니다. 문헌의 발행 시점·판본·확인한 범위를 남기고, 현재 도구 기능·요금·코드 규칙은 오래된 책만으로 업데이트하지 않습니다.

## 학습 방식: 예시 또는 예시 + 실습

카드 본문은 설명·예시를 뒤집어 확인하는 버튼이고 뒷면은 흰 배경·검정 텍스트입니다. 하단의 별도 학습 버튼으로 시각 예시를 엽니다. 두 버튼을 중첩하지 않습니다.

`src/data/learning/entries.json`이 239개 학습 방식과 시각 자료의 기준입니다. `glossary-learning.ts`가 용어 ID로 연결합니다. 현재 `example` 195개, `practice` 44개입니다. 목록과 필터 숫자는 이 데이터에서 계산합니다.

- `example`: 시각 예시 → 관찰 포인트 → 참고 자료(있는 경우) → 기억할 점. 산출물·직무·연구 개념 등에 사용하며 퀴즈와 가짜 조작을 표시하지 않습니다.
- `practice`: 위 시각 자료 다음에 실제 조작이 개념 이해에 도움이 될 때만 직접 해보기를 표시합니다. 간격·레이아웃·반응형·글자 조절, 실제 정보/메모 분류 등이 해당합니다.
- `rationale`: 편집자용 학습 방식 선택 이유이며 학습 화면에 노출하지 않습니다.
- `figure`: 용어에 맞는 원본 시각 자료와 짧은 해설입니다. 결과물은 case-study/persona/journey-map 등 실제 형태로, 원리는 필요한 정확한 SVG로 표현합니다. 단순 텍스트 카드나 장식 도형만으로 다른 개념을 같은 그림처럼 표현하지 않습니다.
- `references`: 확인한 원문 URL, 제목, 관찰할 점. 실제 제품·수업 프로젝트·가상 예시를 구분합니다. 외부 화면을 무단 복제하지 않습니다.
- `practiceReason`: 조작이 실제로 무엇을 학습하게 하는지 설명합니다. 실습 모드에서 필수입니다.

새 용어는 먼저 가장 적합한 시각 예시를 작성합니다. 모든 용어에 실습을 강제하지 않습니다. 실습이 정의와 직접 연결되고 실제 UI 상태 변화를 보여 줄 때만 `practice`를 선택합니다. 생성형 이미지는 정확한 구조 도식의 대안으로 사용하지 않습니다.

`src/data/practice/entries.json`은 이전 236개 활동 데이터를 보관합니다. 현재 공개 여부는 오직 learning mode로 결정합니다. `example` 항목에 이전 활동 데이터가 있어도 실습을 렌더링하지 않습니다. `getGlossaryPractice`는 기억할 점을 재사용하기 위해 원본 활동을 반환할 수 있으므로 노출 판단에는 `getLearningMode`/`hasGlossaryPractice`를 사용합니다.

기존 CTA·햄버거 메뉴·캐러셀은 `lessonId`로 연결하는 전용 데모를 사용합니다. CTA 목록 표시는 `CTA`이며 원래 영어 표제어 `Call-to-action (CTA)`도 검색할 수 있습니다. 화면 내부 예시는 실제 가입·저장·전송을 하지 않습니다.

실습의 시나리오·지시·비교 라벨은 실제 엔진 컨트롤과 일치해야 합니다. 정적 그림을 인터랙티브라고 설명하거나 예제 하나의 조작을 전체 접근성 평가 등으로 확대하지 않습니다. 사용자 입력은 의미를 자동 판정하지 않습니다. 검수에서 실제 클릭 결과·키보드·모바일·초기화·모달 닫기와 포커스 복귀를 확인합니다.

## 학습 자료와 단어장 연결

`/materials`는 학습 가이드·학습 경로·참고 자료를 한곳에서 제공합니다. `src/data/study-materials.ts`가 `editorial/guides-foundation.json`, `guides-practice.json`, `guides-ai.json`의 20개 가이드를 조합합니다. 주제 8개와 수준 3개는 `design-sources.ts`가 정의합니다. 검색·주제·수준 필터는 함께 적용됩니다.

각 가이드는 학습 목표, 개념 설명, 학습용 가상 판단 사례(상황·선택·이유·대안·확인), 적용 과제와 결과물 점검 기준, 흔한 오해, 관련 용어 및 확인한 PDF 페이지를 제공합니다. 과제는 자율 학습용이며 제출·자동 채점·완료 기록 기능이 아닙니다. 회차 일정은 변경하지 않습니다.

- `relatedTermIds`: 기준 용어 ID만 입력합니다. 현재 영어·한국어 표제는 어댑터가 기준 데이터에서 가져옵니다.
- `visualTermId`: 관련 용어의 기존 맥락 예시를 표시합니다. 정적인 예시를 직접 해보기로 부르지 않습니다.
- `sourceRefs`: `sourceId`, 실제 PDF 뷰어의 1부터 센 `pdfPages`, 확인한 `section`, 참조 관계 `relation`을 기록합니다.
- `relation`: `concept`은 정의를 직접 뒷받침하는 본문, `application`은 설계 적용 참고, `context`는 관련 맥락입니다. 관련 단어가 나타난다는 이유만으로 직접 개념 근거를 부여하지 않습니다.
- 관련 용어 링크는 `/glossary?term=영어표제어`로 이동합니다.
- `STUDY_PATHS`는 준비생·경력·프로 디자이너를 위한 읽기 순서입니다. 경력에 따른 자격이나 숙련도를 판정하지 않습니다.
- 공식 웹 자료의 추가 확인은 어댑터의 `supplementalReferences`에 분리합니다. 제공 PDF와 혼동하지 않습니다.

`src/data/editorial/terms-1.json`부터 `terms-3.json`까지는 239개 용어의 실무 해설입니다. `glossary-depth.ts`가 ID로 연결합니다. 각 항목은 주제, 정의, 식별 기준, 실무 상황·판단, 트레이드오프·확인 근거, 혼동 용어, 출처 범위를 갖습니다. 정의를 바꾸면 `glossary.json.description`도 같은 문장으로 갱신해야 합니다. 직접 근거가 없는 용어는 `sourceRefs: []`와 구체적인 `sourceNote`로 편집 해설임을 밝힙니다. 출처를 채우기 위해 무관한 페이지를 연결하지 않습니다.

새 용어를 추가할 때는 기준 표제·학습 방식·맥락 예시와 함께 실무 해설도 추가합니다. 239개 기존 항목을 맞추는 테스트를 승인된 새 목록으로 갱신합니다. 주제·가이드·경로 개수는 데이터에서 계산하며 새 항목을 임의로 기존 ID에 덮어쓰지 않습니다.

원본 PDF·페이지 이미지·책 문장을 그대로 자료실에 복제하지 않습니다. 제공 자료는 분석에 사용하고, LMS에는 새로 작성한 설명·원본 예시·서지 정보만 공개합니다. 비공개 Drive 파일 URL이나 다운로드 버튼을 추가하거나 공유 권한을 넓히지 않습니다. 발췌본·Early Release·오래된 도구 정보의 한계는 참고 자료와 각 출처 영역에 남깁니다.

## Figma

파일: https://www.figma.com/design/XF0sIQq6KmdbIynyXUWmsD

Figma의 통합 목록과 A–Z 카드 카탈로그는 용어 데이터를 기반으로 만든 별도의 편집 가능한 디자인 스냅샷입니다. 앞면과 설명면은 같은 용어의 두 상태이며 서로 다른 용어로 세지 않습니다. 향후 추가 시 알파벳 그룹 안의 영어 순서를 유지하고 재사용 카드 컴포넌트의 인스턴스를 사용합니다.

LMS 데이터 변경이 Figma에 자동으로 동기화되지는 않습니다. 원어 중심 표기 개정과 자료실 가이드가 Figma에도 반영되었다고 추정하지 않습니다. Figma 동기화 작업을 수행할 때 JSON과 Figma의 개수·ID·표기·정렬을 다시 대조합니다. 기존 세 학습 화면의 프로토타입과 신규 카탈로그의 실제 연결 상태는 구분해 확인합니다.

## 콘텐츠 검수와 배포

- 전체 항목의 고유 ID와 필수 필드 누락을 확인합니다.
- 정의에 기능·역할·형태를 혼동한 내용이나 근거 없는 절대 규칙이 없는지 확인합니다.
- 발음과 뜻을 검토하고 예시가 정의를 정확하게 보여 주는지 확인합니다.
- 용어 개수가 늘면 현재 239개를 검증하는 기준 테스트도 승인된 새 항목 수·목록으로 갱신합니다.
- 현재 표기·이전 번역·별칭 검색, 필터 조합, 페이지 이동, 긴 설명, 작은 화면, 기존 실습을 검사합니다.
- 자료실의 가이드 개수·본문·관련 용어 ID, 검색과 빈 결과, 도식 연결, 대화상자 닫기·포커스 복귀를 확인합니다. 관련 용어를 눌러 실제 단어장 검색 결과까지 이동해 봅니다.
- `npm test`, TypeScript 검사, `npm run build` 후 기존 Vercel 프로젝트로 배포합니다.

용어 목록의 기존 출처는 LMS 하단의 원본문서 링크에 남깁니다. 이번에 작성한 활용 예시는 교육용 가상 상황입니다. 외부 스크린샷을 최종 학습 UI로 복제하지 않습니다.

2026-10-31 Drive 자료 기반 개정의 실제 수정 수·출처 범위·검증 결과는 `glossary-drive-content-review.md`에 기록했습니다. 이전 단계의 전체 실습 제작 기록은 현재 학습 방식이나 최신 표기를 대신하지 않습니다.

## 실제 맥락을 담은 시각 예시

`src/components/glossary/contextual/ContextualExample.tsx`는 239개 용어에 대해 명시적으로 등록한 학습용 화면을 연결합니다. `VisualScenes`, `InteractionScenes`, `ArtifactScenes`, `WorkScenes`, `ResearchScenes`가 각각 담당 ID와 렌더러를 내보냅니다. 공통 브라우저·모바일·문서 프레임과 사진·관찰 설명은 `ContextFrame.tsx`를 사용합니다.

- UI 개념은 실제 콘텐츠·내비게이션·상태가 있는 가상 웹/모바일 화면에서 보여 줍니다. 용어 설명을 제품 화면의 본문처럼 배치하지 않습니다.
- 리서치·실무 개념은 페르소나, 저니맵, 인터뷰 기록, 작업 보드, 포트폴리오, 문서 등 해당 산출물 형태로 표현합니다. 직무는 작업 결과와 기여 위치를 연결합니다.
- 큰 구조의 재사용은 허용하되 용어마다 실제 관찰할 대상·내용·강조·해설이 일치해야 합니다. 관련 없는 화면에 용어 이름만 바꾸지 않습니다.
- 기존 도식과 설명은 ‘핵심 구조 살펴보기’에서 펼쳐 볼 수 있습니다. 기본 상태에서는 새 맥락 예시와 설명을 보여 줍니다.
