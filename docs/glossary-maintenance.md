# K-Move 디자인 용어집·학습자료 유지관리

기준일: 2026-11-01 (한국시간). 현재 구성은 `expanded-design-library.md`와 이 문서를 따른다. 학습 대상은 ‘디자이너’ 하나이며 경력별 경로·수준 필터·숙련도 배지를 두지 않는다.

## 현재 범위와 화면 구조

용어집은 **359개(기존 239개 + 신규 120개)**, 학습자료는 **28개 가이드(기존 20개 + 신규 8개)**다. 현재 학습 방식은 **예시 보기 309개, 예시 + 실습 50개**다. 기존 44개 실습에 신규 UI 실습 6개가 더해졌으며, 단순히 활동 데이터가 있다는 이유로 실습으로 세지 않는다. 이 범위가 디자인의 모든 전문 분야를 완전히 망라한다는 뜻은 아니다.

- **용어집 `/glossary`**: 용어를 찾고 뜻·구조·예시를 구분하는 곳이다. 검색과 주제 선택을 우선하고 학습 유형·A–Z는 ‘상세 필터’에 둔다. 한 페이지에 12개 카드를 표시한다.
- **학습자료 `/materials`**: 여러 용어를 연결해 이론과 설계 판단을 공부하는 곳이다. ‘주제별로 이어 배우기’에서 주제 또는 검색으로 가이드를 고른다. 별도 메뉴로 제공하며 용어집으로 리디렉션하지 않는다.
- 용어 카드는 영어 표제어와 `[한국어 발음] / 한국어 뜻`을 먼저 보여 준다. 뒤집은 면의 정의·예시는 흰 배경·검정 텍스트로 유지한다. 카드 뒤집기와 학습 화면 열기는 별도 버튼이며 중첩하지 않는다.
- 용어 상세는 **핵심 구조 / 예시 보기 또는 예시·실습 / 실무 해설**의 세 탭으로 나눈다. 한 패널만 보이고, 처음 방문한 패널의 콘텐츠를 불러온 뒤 탭을 바꿔도 실습 상태를 보존한다. 다른 용어로 전환할 때는 그 용어의 첫 단계부터 시작한다.
- 학습자료는 **주제 → 가이드 목록 → 한 가이드 읽기** 순서다. 본문은 **개념 이해 / 설계 판단 / 내 작업에 적용**의 세 탭으로 나누고, 개념 문단은 첫 항목만 펼친다. 시각 예시·관련 용어·출처는 필요할 때 펼친다.
- 주제 분류는 `design-sources.ts`의 10개 `TOPICS`를 공유한다. 목록 수·필터 수·페이지 수는 데이터로 계산하며 화면에 숫자를 별도로 하드코딩하지 않는다.

정보를 줄이기 위해 본문을 삭제하지 않는다. 정의·핵심 설명을 먼저 보여 주고 사례·대안·검증·출처의 열람 순서를 나눈다. 실제 실습의 지시·연습 상황과 정적 예시의 관찰 안내를 구분한다.

## 기준 데이터와 표기

기존 용어의 기준은 `src/data/glossary.json`이다. 신규 용어는 `src/data/expansion/`의 네 팩을 사용한다. `glossary.ts`가 두 집합을 합쳐 검색·A–Z 정렬·카드 목록을 만든다. 기존 239개를 새 팩에 복제하거나 같은 뜻의 표기를 늘려 개수를 부풀리지 않는다.

| 필드            | 작성 기준                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `id`            | 변경하지 않는 고유 식별자. 새 항목은 중복되지 않는 영문 kebab-case를 사용한다.                                            |
| `english`       | 영어 표제어. 이 값으로 A–Z 정렬하고 첫 알파벳을 계산한다.                                                                 |
| `pronunciation` | 괄호 없이 한국어 독음을 입력한다. 화면에서 `[...]`를 붙인다. 한글 독음은 학습용 근사 표기이며 IPA가 아니다.               |
| `korean`        | 디자인 현장에서 자연스럽게 쓰는 한국어 명칭. 통용 외래어·원어·약어를 억지로 직역하지 않는다.                              |
| `description`   | 개념을 정확히 구분하는 정의. 실무 판단·주의사항은 해설 데이터로 분리하며 새 본문에 `[실무 참고]` 구분자를 넣지 않는다.    |
| `example`       | 해당 개념이 드러나는 구체적인 디자인·리서치·업무 상황. 정의를 그대로 반복하지 않는다.                                     |
| `aliases`       | 이전 번역, 통용 표기와 띄어쓰기 변형 등 검색 별칭. 표제어를 바꾸어도 이전 표현으로 찾을 수 있게 유지한다.                 |
| `lessonId`      | 기존 CTA·햄버거 메뉴·캐러셀 전용 데모의 `cta`, `hamburger`, `carousel` 연결값. 신규 일반 용어에 임의로 재사용하지 않는다. |

`Case study / 케이스 스터디`, `Fidelity / 피델리티`, `CTA`, `IA`, `WCAG`처럼 익숙한 전문 용어는 살리고 정의에서 의미를 설명한다. 접근성·근접성·서체·시각적 위계처럼 자연스럽고 정확한 한국어도 유지한다.

표기를 바꿀 때는 기준 항목뿐 아니라 같은 ID의 학습 그림·관찰 포인트·실습 지시·기억할 점·렌더러의 고정 문구를 확인한다. 기존 세 전용 데모의 표기는 `VisualGlossaryLesson.tsx`에도 있으므로 함께 대조한다. 문자열 치환 후에는 한국어 조사·띄어쓰기와 개념이 달라진 문장이 없는지 검토한다.

UI를 외형만으로 설명하거나 버튼과 CTA를 같은 뜻으로 다루지 않는다. 로파이·하이파이, 와이어프레임·목업·프로토타입은 다른 구분이며 필수 제작 순서로 단정하지 않는다. 특정 간격·컬럼 수·인쇄 여백·심리 원칙을 모든 환경의 절대 규칙으로 옮기지 않는다. 현재 도구 기능·요금·구현 규칙은 오래된 문헌만으로 갱신하지 않는다.

## 네 가지 확장 팩과 시각 예시

신규 120개는 다음 네 팩에 각각 30개씩 들어 있다.

| 데이터                       | 범위                              | 전용 예시 렌더러                   |
| ---------------------------- | --------------------------------- | ---------------------------------- |
| `expansion/visual.json`      | 조형 원리·타이포그래피·색상       | `expanded/VisualExamples.tsx`      |
| `expansion/production.json`  | 그래픽·색 관리·인쇄·브랜딩        | `expanded/ProductionExamples.tsx`  |
| `expansion/interaction.json` | UI 패턴·상태·디자인 시스템·접근성 | `expanded/InteractionExamples.tsx` |
| `expansion/research.json`    | 리서치 방법·근거 해석·콘텐츠      | `expanded/ResearchExamples.tsx`    |

데이터 경로의 기준 디렉터리는 `src/data/`, 렌더러의 기준 디렉터리는 `src/components/glossary/`다. `expansion/manifest.json`은 팩별 ID를, `expansion/index.ts`는 공통 용어·웹 출처 집합을 관리한다. `expanded/ExpandedExample.tsx`가 명시적으로 등록한 ID를 해당 렌더러에 연결한다. 미등록 용어에 관계없는 일반 예시를 자동 대입하지 않는다. 핵심 구조는 `expanded/ExpandedConcept.tsx`가 네 팩의 `*Concept.tsx`로 연결한다. 단순 텍스트 카드 대신 용어의 형태·거리·상태·관계를 정확히 드러내는 도식을 먼저 제공한다.

각 팩의 `terms`에는 표제·정의·예시 외에 `topic`, `essential`, `application`, `critique`, `confusedWith`, `sourceIds`, `figure`가 들어 있다. `sources`에는 실제 확인한 공식·저자 자료의 고유 ID·제목·URL·설명 범위를 기록한다. 용어의 `sourceIds`는 존재하는 출처를 가리켜야 하고, `confusedWith`는 기존·신규 전체 목록에 존재하는 용어 ID를 사용해야 한다.

그림은 정확한 HTML/CSS/SVG와 원본 학습용 레이아웃으로 작성한다. 조형·타입 해부, 인쇄 경계·분판, UI 상태, 연구 기록 등 실제 관찰할 대상이 드러나야 한다. 큰 구조를 재사용하더라도 용어별 내용·표시·비교 기준을 바꾸며, 이름만 바꾼 텍스트 카드나 장식 도형으로 서로 다른 개념을 설명하지 않는다. 생성형 이미지를 정확한 구조 도식의 대안으로 사용하지 않는다.

기존 시각 예시는 `contextual/ContextualExample.tsx`와 `VisualScenes`, `InteractionScenes`, `ArtifactScenes`, `WorkScenes`, `ResearchScenes`에서 연결한다. 공통 프레임은 `ContextFrame.tsx`를 사용한다. UI 개념에는 가상 웹·모바일 화면을, 리서치·실무 개념에는 페르소나·저니맵·인터뷰 기록·작업 보드·포트폴리오·문서 등 적합한 산출물을 쓴다.

정적 화면의 컨트롤 모양을 실제 조작으로 설명하지 않는다. 가상 수치·프로젝트·연구 기록은 교육용 설정으로 표시하고 실제 성과로 표현하지 않는다. 화면상 색 비교를 실제 ICC 변환·인쇄 결과로 오인시키지 않는다. 사진 파일과 사용 근거는 `public/glossary/SOURCES.md`에 기록한다. Mobbin은 구조 분석 참고이며 스크린샷을 최종 학습 UI로 복제하지 않는다.

## 학습 방식과 실제 실습

`glossary-learning.ts`가 기존 `learning/entries.json`과 신규 팩을 합쳐 학습 방식을 결정한다. 현재 309개는 `example`, 50개는 `practice`다. 모든 용어에 실습을 강제하지 않으며 조작이 정의를 이해하는 데 도움이 될 때만 추가한다.

- `example`: 핵심 구조와 실제 맥락의 시각 예시를 관찰하고 실무 해설로 이어진다. 산출물·직무·연구 개념 등에 불필요한 퀴즈나 가짜 조작을 붙이지 않는다.
- `practice`: 시각 예시와 함께 실제 선택·조정·분류 등에 따른 상태 변화를 보여 준다. 시나리오·지시·비교 라벨은 실제 컨트롤의 동작과 일치해야 한다.
- 기존 학습 항목의 `rationale`은 편집자용 방식 선택 이유다. `figure`는 구조·관찰 포인트·해설을, `references`는 확인한 외부 사례의 URL·제목·관찰할 점을 갖는다. `practiceReason`은 실습의 학습 목적을 기록한다.
- `practice/entries.json`은 이전 236개 활동을 보관하지만 공개 여부는 학습 방식으로 결정한다. `getGlossaryPractice`가 자료를 반환해도 곧바로 실습으로 노출하지 않는다. 노출과 개수는 `getLearningMode`·`hasGlossaryPractice`를 사용한다.
- CTA·햄버거 메뉴·캐러셀은 `lessonId`로 연결하는 전용 데모를 유지한다. `CTA` 목록 표시는 원래 표제어 `Call-to-action (CTA)` 검색과 함께 지원한다. 샘플 가입 화면은 실제 가입·저장·전송을 하지 않는다.

신규 실습 6개는 `accordion`, `tabs`, `checkbox`, `radio-button`, `toggle-switch`, `progressive-disclosure`다. 등록은 `src/data/expansion/practice.ts`, 동작은 `src/components/glossary/expanded/InteractionLab.tsx`에서 관리한다. `glossary-learning.ts`의 학습 방식과 `glossary-practice.ts`의 실습 식별, `GlossaryLearningLesson.tsx`의 렌더링이 이 등록 정보를 함께 사용한다.

새 실습은 동작을 먼저 구현하고 적합한 ID를 등록한다. 단순히 모드를 `practice`로 바꾸거나 버튼 모양을 추가해서 완료 처리하지 않는다. 직접 해보기가 없는 신규 용어는 정확한 정적 예시로 유지한다. 실습은 의미를 자동 판정하는 기능이나 학습 완료 기록이 아니다. 각 실습의 실제 클릭·키보드·초기화 결과를 확인하고, 탭을 오갈 때의 상태 유지와 모달 닫기 후 포커스 복귀를 검사한다.

## 주제별 학습자료와 용어 연결

`src/data/study-materials.ts`는 기존 `editorial/guides-foundation.json`, `guides-practice.json`, `guides-ai.json`의 20개와 `expansion/guides.json`의 8개를 합쳐 28개 가이드를 제공한다. 가이드 수와 주제별 개수는 데이터에서 계산한다.

각 가이드는 학습 목표, 개념 설명, 학습용 가상 판단 사례(상황·선택·이유·대안·확인), 적용 과제·결과물 점검 기준, 흔한 오해, 관련 용어와 근거를 보존한다. 과제는 자율 학습용이며 제출·자동 채점·완료 기록 기능이 아니다.

- `relatedTermIds`: 기준 용어 ID를 입력한다. 화면의 영어·한국어 표제는 어댑터가 전체 용어 데이터에서 가져온다.
- `visualTermId`: 실제로 존재하는 관련 용어의 시각 예시를 연결한다. 정적인 예시를 직접 해보기로 부르지 않는다.
- `getGuidesForTerm(termId)`: 관련 용어 ID 또는 `visualTermId`가 정확히 일치하는 가이드만 연결한다. 제목 부분 일치나 같은 주제라는 이유로 추천하지 않는다.
- 각 가이드의 ‘내 작업에 적용’ 끝에서는 같은 주제의 다음 가이드 한 개를 제공하며, 마지막에는 다음 가이드를 생략한다. 완료 기록이나 강제 진도를 주장하지 않는다.
- 용어의 ‘이어서 공부하기’는 `/materials?guide=<가이드 ID>`로 이동한다. 학습자료의 관련 용어는 `/glossary?term=<영어 표제어>`로 연결한다.
- 자료 페이지는 유효한 가이드 URL을 직접 열 수 있어야 한다. 없는 ID에는 빈 화면 대신 안내와 목록 탐색을 제공한다. 목록으로 돌아갈 때 검색·주제 선택과 원래 링크의 포커스를 보존하고 브라우저 뒤로·앞으로 이동도 확인한다.
- 가이드의 ‘개념 이해 / 설계 판단 / 내 작업에 적용’ 탭은 하나만 보인다. 핵심 문단의 펼침 상태를 보존하고, 시각 예시는 처음 펼칠 때 불러온다. 출처는 마지막의 닫힌 영역에 둔다.

## 실무 해설과 출처 관리

기존 용어의 해설은 `editorial/terms-1.json`부터 `terms-3.json`까지 239개다. 신규 해설은 네 확장 팩에서 가져오고 `glossary-depth.ts`가 전체 359개를 ID로 연결한다. 해설은 식별 기준, 적용 상황·선택, 트레이드오프·확인 근거, 혼동 개념과 출처를 갖는다. 기존 정의를 바꾸면 해당 해설의 `definition`과 `glossary.json.description`도 일치시킨다.

제공 PDF **10종**의 서지·판본·확인 페이지·검토 한계는 `design-sources.ts`와 각 항목의 `sourceRefs`에 보존한다. 본문은 자료에서 얻은 개념과 판단 기준을 직접 설명한다. 책 카탈로그·PDF 다운로드·읽은 범위 설명을 학습 첫 화면에 전면 배치하지 않는다.

| 근거 필드                                      | 관리 기준                                                                    |
| ---------------------------------------------- | ---------------------------------------------------------------------------- |
| `sourceRefs.sourceId`                          | 실제 검토한 PDF의 등록 ID.                                                   |
| `pdfPages`                                     | 제공 PDF 뷰어의 첫 페이지부터 1로 센 쪽수. 인쇄된 책 쪽수와 혼동하지 않는다. |
| `section`                                      | 확인한 본문 범위. 목차의 단어 등장만으로 본문을 검토했다고 쓰지 않는다.      |
| `relation: concept`                            | 정의를 직접 뒷받침하는 개념 근거.                                            |
| `relation: application`                        | 설계 적용을 위한 참고.                                                       |
| `relation: context`                            | 관련 맥락. 직접 개념 근거와 구분한다.                                        |
| `sourceNote`                                   | 직접 근거가 없는 기존 용어의 편집 해설 범위 등 구체적인 한계.                |
| 신규 팩의 `sourceIds`·`sources`                | 실제 확인한 웹 자료. 제공 PDF의 근거인 것처럼 쪽수를 만들지 않는다.          |
| 가이드의 `references`·`supplementalReferences` | 공식 웹 자료의 보강 근거. PDF 출처와 분리해 제목·URL·확인 범위를 기록한다.   |

추적 가능한 근거는 용어·가이드 맨 아래의 작은 **출처·제작 정보**에 기본으로 닫아 둔다. 표시를 줄인다는 이유로 출처 관계·한계를 삭제하거나, 읽지 않은 범위까지 완독·검증했다고 바꾸지 않는다. 확인한 사실과 교육용 적용·편집 해설을 구분하고 무관한 페이지로 빈 출처를 채우지 않는다.

원본 PDF·책 문장·페이지 이미지를 그대로 복제하지 않는다. 비공개 Drive 파일 URL이나 다운로드 버튼을 추가하거나 공유 권한을 넓히지 않는다. 실제 제품·포트폴리오 등 학습에 도움이 되는 확인된 외부 사례 링크는 ‘실제 사례 더 보기’로 남기며 내부 문헌 출처와 구분한다.

## 새 콘텐츠를 추가하는 순서

1. 기존 359개와 별칭을 검색해 이미 있는 개념인지 확인한다. 새 ID·영어 표제·자연스러운 한국어 명칭·학습 목적을 정한다.
2. 적합한 확장 팩에 정의·예시·실무 해설·혼동 용어·근거를 함께 작성하고 `manifest.json`에 ID를 등록한다. 새 팩이 필요하면 `expansion/index.ts`와 예시 그룹 연결도 추가한다.
3. 해당 `expanded/*Examples.tsx`와 CSS에 용어에 맞는 실제 관찰 대상을 구현한다. 명시적 ID 연결을 확인하고 작은 화면에서도 읽히게 만든다.
4. 시각 예시만으로 충분한지 판단한다. 실제 조작이 필요한 경우에만 실습 엔진과 `expansion/practice.ts` 등록, 학습 방식·렌더링·상태 검사를 함께 추가한다.
5. 필요한 가이드의 `relatedTermIds`·`visualTermId`를 정확한 ID로 연결한다. 신규 가이드라면 개념·판단·적용 과제·결과물 기준·출처를 모두 작성한다.
6. 새 항목 수와 목록을 콘텐츠 검증 기준에 반영한다. 원본 239개 보존 검사와 새 항목 검사를 구분하며, 기존 ID를 덮어쓰거나 원본 보존 검사를 느슨하게 만들지 않는다.
7. 실제 검수 후에만 완료 결과를 기록하고 운영 배포를 진행한다. 수업 일정·인증·백엔드는 콘텐츠 추가만을 이유로 변경하지 않는다.

## Figma와 검수·배포

기존 디자인 파일: https://www.figma.com/design/XF0sIQq6KmdbIynyXUWmsD

Figma의 목록·A–Z 카드 카탈로그는 별도의 편집 가능한 디자인 스냅샷이다. 앞면과 설명면은 같은 용어의 두 상태이며 서로 다른 용어로 세지 않는다. 후속 작업에서는 알파벳 그룹 안의 영어 순서를 유지하고 재사용 카드 컴포넌트를 사용한다.

LMS 데이터 변경은 Figma에 자동 동기화되지 않는다. 359개 확장·새 표기·학습자료 분리·실습 연결이 Figma에도 반영됐다고 추정하지 않는다. 실제 동기화 작업 때 JSON과 Figma의 개수·ID·표기·정렬·프로토타입 연결을 다시 대조한다. 정적 시안을 작동하는 인터랙션이라고 설명하지 않는다.

검수에는 다음 항목을 포함한다.

- 전체 고유 ID·필수 필드·별칭·혼동 용어·시각 예시·출처 연결과 원본 239개 보존.
- 359개 용어, 28개 가이드, 309개 예시와 50개 실습의 데이터 일치. 신규 승인 항목을 더한 경우 실제 수에 맞춰 갱신.
- 한국어 표기·정의·예시의 개념 정확성, 근거 없는 절대 규칙과 실제/가상 데이터 혼동 여부.
- 용어 검색·주제·상세 필터 조합, 12개 단위 페이지 이동·초기화·빈 결과, 긴 설명·작은 화면.
- 용어 세 탭의 단일 표시, 키보드 좌우/Home/End 이동, 방문한 실습의 상태 유지, 다른 용어 전환과 모달 닫기·포커스 복귀.
- 기존 세 전용 데모와 공개 기존 실습, 신규 6개 실습의 실제 조작·키보드·초기화 결과. 정적 예시가 조작 가능한 것처럼 오인되지 않는지 확인.
- 두 메뉴와 `/materials?guide=` 직접 진입, 주제·검색·전체 목록·빈 결과, 한 가이드 읽기, 세 탭과 펼침을 통한 28개 전체 본문·과제·출처 접근.
- 자료 목록 복귀 시 검색·주제·원래 링크 포커스 유지, 브라우저 뒤로·앞으로 이동, 데스크톱·모바일 가독성과 수평 넘침.
- TypeScript·관련 테스트·`npm test`·`npm run build`를 변경 범위에 맞게 수행하고, 운영 반영 시 기존 Vercel 프로젝트·팀·커밋·production 상태와 실제 배포본을 확인.

이 문서는 현재 구조와 유지 기준이며 배포 완료 증명이 아니다. 실제 수행한 검증은 `expanded-design-library.md`에 기록하고 운영 반영은 GitHub 병합 커밋과 Vercel production 상태를 별도로 확인한다. `glossary-drive-content-review.md`, `pdf-editorial-review.md`, `unified-designer-learning.md` 등의 과거 검토 기록은 출처 범위·변경 이력을 보존하는 자료다. 과거 메뉴 결정·개수·테스트 통과 결과를 현재 구현이나 새 검증 결과로 대신 사용하지 않는다.
